# MLOps: Управлінський PM-пакет

## Мета завдання
Сформувати комплексний управлінський PM-пакет документів для підготовки ML-рішення (моделі класифікації зображень) до staging/production. Мета проєкту — не писати код власноруч, а правильно поставити задачу команді розробників, проконтролювати delivery-артефакти (Docker-образи), оцінити результати оптимізації та мінімізувати інфраструктурні ризики.

## Короткий контекст
AI/ML-команда розробила модель класифікації зображень на базі `torchvision.models`. Для її безпечного та відтворюваного розгортання прийнято рішення використати контейнеризацію (Docker). Необхідно підготувати два образи: `ml-infer-fat:1.0` (простий, для першої перевірки) та `ml-infer-slim:1.0` (оптимізований, на `python:3.13-slim`, multi-stage). Головна умова — збереження ідентичності результатів inference при зменшенні розміру образу.

## Навігація по PM-артефактах (як використовувати файли)
Цей репозиторій містить наступні документи:
1. `project_brief.md` — Описує бізнесовий та технічний контекст. Використовувати для синхронізації розуміння проєкту всіма учасниками.
2. `ai_ml_team_task.md` — Оформлена технічна задача (як для Jira/GitLab). Використовувати для передачі роботи AI/ML інженерам.
3. `acceptance_criteria.md` — Критерії приймання та Definition of Done. Використовувати для фінальної прийомки задачі.
4. `docker_image_review.md` — Чекліст для технічного рев'ю Dockerfile та залежностей. Використовувати під час Code Review.
5. `optimization_report_review.md` — Шаблон для порівняння fat та slim образів. Заповнити після отримання метрик від команди.
6. `compose_readiness_checklist.md` — Чекліст для перевірки готовності локального середовища. Використовувати для тестування інтеграції сервісів.
7. `risk_register.md` — Реєстр потенційних ризиків проєкту та шляхи їх пом'якшення. Використовувати на мітингах статусу проєкту.
8. `stakeholder_summary.md` — Короткий статус-репорт зрозумілою мовою. Використовувати для комунікації з бізнесом/керівництвом.

## Questions to AI/ML Team
Для успішного прийняття роботи PM має отримати відповіді на такі запитання:
* Який фінальний model artifact використовується?
* Яка його версія?
* Який input/output format очікується?
* Чи підтверджена сумісність із python:3.13?
* Чи підтверджена сумісність із python:3.13-slim?
* Чи сумісні torch, torchvision, pillow з обраною версією Python?
* Чи є .dockerignore?
* Чи збігається inference для fat і slim?
* Чи є report.md із порівнянням?
* Чи README містить команди build/run?
* Чи потрібен Docker Compose для локального стенду?
* Чи немає секретів у Compose?

## Команди для перевірки результатів
Якщо артефакти вже готові, ви можете використати наступні команди для базової перевірки:
* **Збірка Fat образу:** `docker build -t ml-infer-fat:1.0 -f Dockerfile.fat .`
* **Збірка Slim образу:** `docker build -t ml-infer-slim:1.0 -f Dockerfile.slim .`
* **Перевірка розміру образів:** `docker images | grep ml-infer`
* **Запуск локального стенду:** `docker compose up --build`
