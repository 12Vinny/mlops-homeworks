# Бізнесовий та технічний контекст проєкту: Контейнеризація ML-моделі

## Бізнесовий контекст та мета
Наша команда підготувала нову модель класифікації зображень (на базі torchvision.models). Для того щоб інтегрувати цю модель у фінальний продукт, нам потрібен працюючий та відтворюваний inference (процес отримання передбачень на нових даних). Контейнеризація через Docker є обраним delivery-артефактом, оскільки вона гарантує, що модель працюватиме однаково на будь-якому середовищі, ізолює залежності та дозволяє зручно передавати готове рішення між командами (AI/ML, DevOps, Backend).

## Технічний контекст та архітектура рішення
У рамках цієї задачі очікується створення двох варіантів Docker-образу:
1. **Fat image (ml-infer-fat:1.0):** Базовий, неоптимізований образ. Його головна мета — забезпечити швидку, гарантовану працездатність моделі "з коробки" для первинної перевірки. Він містить усі необхідні залежності у найпростішому вигляді.
2. **Slim image (ml-infer-slim:1.0):** Оптимізований образ, спеціально підготовлений для production-подібних середовищ. Він має базуватися на python:3.13-slim та збиратися через multi-stage build, щоб суттєво зменшити розмір, підвищити безпеку та пришвидшити розгортання.

## Ключові вимоги до результату
* **Незмінність результату:** Оптимізація образу (перехід від fat до slim) жодним чином не повинна вплинути на роботу самої моделі. Inference має бути ідентичним для обох образів при однаковому input-файлі.
* **Відтворюваність та готовність:** Результат (Docker-образи та скрипти) має бути повністю придатним для перевірки та запуску локально розробниками, у пайплайнах CI/CD, а також на staging-середовищі без додаткового ручного налаштування чи встановлення прихованих залежностей.
