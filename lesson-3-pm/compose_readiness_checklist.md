# Checklist готовності локального стенду (Docker Compose)

Цей чекліст використовується для перевірки того, чи можна підняти всю локальну інфраструктуру (API, бази даних, кеш, моніторинг) однією командою без додаткових ручних налаштувань.

## Інфраструктура та сервіси
* Чи наявний конфігураційний файл `compose.yaml` (або `docker-compose.yml`)?
* Чи описаний сервіс `model-api` (model service або model runtime)?
* Чи описані всі залежні сервіси (Redis, PostgreSQL, сервіси моніторингу)?
* Чи всі сервіси піднімаються автоматично та не потребують ручного запуску скриптів всередині контейнерів?

## Мережа та API
* Чи правильно налаштований мапінг портів (ports) для доступу до API з хост-машини?
* Чи є робочий `health` endpoint (наприклад, `/health` або `/ping`) для перевірки статусу сервісу?
* Чи є робочий `predict` endpoint для виконання безпосередньо inference?

## Безпека, конфігурація та ізоляція
* Чи винесені всі змінні конфігурації у файл `.env`?
* Чи відсутні production-секрети (реальні паролі, токени, ключі доступу) у файлах `compose.yaml` та захардкоджені в репозиторії?
* Чи локальний стенд повністю ізольований (не підключений до production DB, production Redis або production черг завдань)?

## Документація
* Чи описана команда запуску (`docker compose up --build`) у загальному файлі `README.md`?

## Фінальний висновок
**Локальний стенд можна вважати готовим**, якщо всі сервіси піднімаються однією командою (`docker compose up --build`), а test prediction виконується без жодних додаткових ручних дій.
